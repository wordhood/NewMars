# NewMars

2D 火星沙盒游戏的技术原型。Godot 4.7 + GDScript。

**它验证的不是"画面上有什么"，而是四条架构决定能不能站住。**

---

## 跑起来

```
1. 打开 Godot
2. 项目管理器 → 导入 → ⌘⇧G 粘贴 ~/Workspace/NewMars → 选 project.godot
3. 按 F5
```

或者终端一行命令直接跑游戏（不开编辑器）：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path ~/Workspace/NewMars
```

### 操作

| 键 | 作用 |
|---|---|
| `A` `D` 或 `←` `→` | 移动 |
| `空格` 或 `W` | 跳跃（轻按小跳，长按大跳） |
| 鼠标左键 | 挖掘 |

### 进去先试这四件事

| # | 试什么 | 你会看到 |
|---|---|---|
| 1 | **一直按 `D` 往右走** | 走到世界尽头不会停，会从左边出来 —— 而且**看不出一丝接缝** |
| 2 | **在 0% 附近左右各挖几格** | 地形是连着的，没有断口、没有错位 |
| 3 | **按 `Q` 切到水冰，右键往脚下放** | 能把自己垫高。这就是以后"建造"的原型 |
| 4 | **按 `R` 下到地核，然后往下挖** | ★ **穿过球心 —— 画面旋转半圈，机器人位于另一半球的球心** |

第 4 条是这个原型最重要的东西。HUD 上的「对跖点」会实时告诉你：从脚下挖穿球心，会从哪一列出来。

穿越过程：到达球心 → 画面旋转 180° → 在另一半球的球心恢复操作。球心转场用时 2.10 秒，接近球心时提前转向。

## 四条架构决定，分别落在哪一行

### ① 周期地形 —— 世界首尾天然闭合

> `world.gd` → `sample_height_noise()`

把世界的 x 映射成角度，在**圆上**采样噪声：

```gdscript
var theta := TAU * float(x) / float(WORLD_W)
return _n_height.get_noise_2d(cos(theta) * CIRCLE_R, sin(theta) * CIRCLE_R)
```

`(cos θ, sin θ)` 绕完一圈天然回到起点，所以 `x = 0` 和 `x = WORLD_W` 处的噪声值**完全相同**。地形不需要事后缝合，因为它一开始就没有缝。

地下部分需要「X 周期 + Y 自由」，用的是把 3D 噪声在**圆柱面**上采样（`sample_cave_noise()`）。

> ⚠️ **最容易踩的坑：频率。**
> 噪声在半径 `CIRCLE_R = 64` 的圆上采样，圆周长 ≈ 402 单位。
> `frequency = f` 意味着绕星球一圈有 `402·f` 个起伏。
>
> | 频率 | 结果 |
> |---|---|
> | `0.018` | 约 7 个起伏，平缓山丘 ✅ |
> | `0.9` | 约 360 个起伏，退化成锯齿随机噪声 ❌ |
>
> 第一版就是给成了 0.9，被自检里的对照组当场抓住。

### ② 坐标环绕 —— 左右走永远走不到尽头

> `world.gd` → `wrap_x()`

```gdscript
return ((x % WORLD_W) + WORLD_W) % WORLD_W
```

必须是这个三重取模 —— GDScript 的 `%` 对负数返回负数，直接写 `x % WORLD_W` 会让 `x = -1` 变成 `-1` 而不是 `WORLD_W - 1`。

`wrap_delta_x()` 则是算「环形最短距离」用的。**算距离时必须用它**，否则站在接缝边上会出现"明明贴着却够不着"的怪现象。

### ③ 环绕渲染 —— 查数据用环绕坐标，画图用展开坐标

> `world.gd` → `_draw()`

```gdscript
for tx in range(x0, x1 + 1):
    var t: int = _tiles[_idx(wrap_x(tx), ty)]                       # ← 查数据：环绕
    if t == Tile.AIR: continue
    draw_rect(Rect2(tx * TILE, ty * TILE, TILE, TILE), COLORS[t])   # ← 画图：展开
```

`tx` 可以是负数，也可以超过 `WORLD_W`，画面照样连续。
**这就是整个环形渲染的全部秘密：一个接缝分支都不需要。**

### ④ ★ 挖穿球心 —— 视角翻转与向心重力

> `main.gd` → `_run_gravity_flip()` / `_finish_crossing()`
> `world.gd` → `antipode_x()`

世界的纵坐标就是**离球心的距离**：

```
y = 0            地表（r = R）
   ↓
y = 138          地核岩层顶部（CORE，可挖穿）
y = 150          扩大的地心空腔顶部（球心前 32 格）
y = 166          进入最后 16 格低重力视角渐变带
y = 182          ★ 球心线 —— 越过它就算穿过了星球中心
y = 184          下方实体岩层开始（保留两格穿越净空）
y = 246          扩展后的方块存储边界
```

玩家挖穿地核岩、掉进地心空腔、自由落体越过球心线 → 触发穿越。

#### 到达球心后旋转半圈

球心前的空腔由 10 格扩大到 32 格；进入最后 16 格时，镜头随接近程度提前缓慢转向，最多 24°。
到达球心后，再用 2.10 秒完成剩余角度，累计仍为半圈；车体穿过球心并转向落脚处。
离开过渡带时视角平滑恢复，落地后不会累计额外旋转或缩放。
结束时切换到对跖列，并把目标半球的地形投影到球心另一侧。
镜头保持半圈后的角度：**地表在头顶，重力在画面中朝下、指回球心**。
两侧岩层在旋转过程中提前交接，不在最后一帧切换；镜头与车体采用两端速度、加速度均为零的缓动。
车体转动略滞后于镜头，带轻微拉远、深部岩尘、暖色反光和落地履带缓冲。
岩室留出转向净空，HUD 保持固定行高。
渲染、碰撞、鼠标挖掘和放置都使用同一套半球坐标换算。

机器人抵达目标半球的球心岩室，履带落在地核地面上，身体位于球心线外约 11 像素。
岩室提供支撑并停止穿越运动，不会靠惯性自动升到地表；不操作时会站稳。
洞室扩大至底部 9 格宽、5 格高，两侧岩壁供履带攀附，头顶地核岩在挖掘范围内。
落脚位嵌入连续地层，远处以缓坡接回洞顶；洞室有小拱顶，不再单独生成突出的窄方柱。

**先走到侧壁，再把鼠标指向头顶，按住空格（或 W）和左键，沿岩壁向上攀附开挖。**
履带攀附提供克服重力的力；松开后恢复重力运动。没有邻近岩壁时不能在空中飞升。
也可以用普通跳跃和放置方块搭建上行路线。挖掉脚下的地核，则可再次穿过球心。
已经挖出的上行通道会保留；每次到达仅恢复脚下的落脚格。
球心下方的方块范围延伸到 64 格，除了两格穿越净空，其余生成可挖地核岩。
`STORAGE_H` 统一控制数据、渲染、碰撞与放置的下界，旧 `WORLD_H` 不再截断下方岩层。

球体采用**均匀密度近似**：内部重力与离球心的距离成正比，球心为零；
外部按距离平方反比衰减。平均地表作为参考半径，洞穴、矿物不单独计算质量。
半球投影和转场中的运动属于游戏表现，不模拟完整球面轨迹。

> ### ⚠️ 这个架构唯一的"税"
> 任何**不周期**的东西（插的旗子、建好的基地、别的玩家），放到接缝附近时必须自己处理显示，否则会看到它闪一下。地形本身没有这个问题，因为它天生就是周期函数。

### 自检里最值得看的两项

**`[4] 周期地形`** 用的是**对照实验**，不是简单断言：

```
接缝落差         = 0 格
相邻列平均落差   = 0.48 格
随机两列平均落差 = 6.65 格     ← 对照组
```

判据是：**接缝的落差应该像"相邻两列"，而不是像"随机两列"。**
这里 6.65 / 0.48 = **13.6 倍**，周期性成立。

**已实测：** 把 `sample_height_noise()` 改成朴素采样 `get_noise_2d(float(x), 0.0)` 之后，接缝落差立刻从 **0 格变成 11 格**，测试变红。

**穿越检查** 会让玩家掉到球心，验证半圈旋转、对跖列球心落点、球心站立、逆重力攀岩开挖、另一半球的地表操作，以及再次穿越：

```
入口 x=200   →   期望对跖点 x=456
实际落点 x=456   （差 0.0 格）
```

## 想改哪里？调参速查

| 想改什么 | 改哪 |
|---|---|
| 世界多大 | `world.gd` 的 `WORLD_W` / `WORLD_H`（`WORLD_W` 必须是偶数，否则对跖点会偏一格） |
| 地核多深 | `world.gd` 的 `CORE_ROCK_TOP` / `CORE_CAVITY_TOP` / `CORE_CENTER_Y` |
| 翻转演出的快慢 | `main.gd` 的 `FLIP_TIME`（现在 2.10 秒完成剩余半圈角度） |
| 山有多高多密 | `world.gd` → `_make_noise()` 里 `_n_height.frequency`（**先看上面的频率说明**），和 `generate()` 里的 `HEIGHT_AMP` |
| 洞穴多少 | 同上，`_n_cave.frequency` 和 `generate()` 里的阈值 `0.35` |
| 矿脉多少 | 同上，`_n_ore.frequency` 和阈值 `0.45` / `-0.50` |
| 方块颜色 | `world.gd` 的 `COLORS` 字典 |
| 挖矿产出 | `world.gd` 的 `YIELD` 字典 |
| 玩家手感 | `player.gd` 顶部的 `SPEED` / `ACCEL` / `JUMP_V` / `GRAVITY` / `COYOTE` |
| 按键 | `project.godot` 的 `[input]` 段（或在编辑器：项目 → 项目设置 → 输入映射） |

改完地形参数后**跑一次 `selftest.gd`**，`[8] 世界成分报告` 会打印每个方块类型的占比、地下空洞率、地表起伏统计。
